# 三位数评论筛选与统计

在已登录的浏览器资料基础上，从抖音网页实际加载的评论和回复中筛选三位数，并生成类似参考图片的次数表。Tauri 界面已接入采集和报表读取。

## 桌面界面

运行 `npm run tauri -- dev`，粘贴分享文案或链接，选择评论发布时间段和最小出现次数（至少 2），然后点击“开始提取号码”。桌面界面默认滚动到网页提示顶层评论没有更多；采集后修改条件，可以点击“应用筛选到已采集评论”直接重新统计本地记录。起止时间使用本机时区，包含选择的结束分钟。结果区可搜索号码。点击“打开报表文件夹”可查看 TXT、CSV、JSON。登录失效时点击“登录失效？打开扫码窗口”，在打开的 Chrome 中扫码；界面会等待登录状态更新。

本次更新前保存的评论记录不含发布时间，无法对其使用时间筛选；此时请重新采集视频。新采集记录包含每条评论的发布时间。

应用通过本机 Node.js 和 Chrome 运行采集脚本。当前安装包会包含脚本及 Playwright Core，运行机器仍需安装 Node.js 和 Chrome。桌面界面的报告保存在应用数据目录；命令行默认写入仓库的 `.phase1/`。

## 使用

快速验证前几批评论：

```powershell
npm run numbers:collect -- --headless --scrolls 10 --replies 1 '<抖音视频链接>'
```

尽量滚动到网页提示顶层评论已无更多：

```powershell
npm run numbers:collect -- --until-end '<抖音视频链接>'
```

指定发布时间范围和最小出现次数（命令行使用带时区的 ISO 时间，结束时间含边界）：

```powershell
npm run numbers:collect -- --headless --until-end --from 2026-10-08T00:00:00.000Z --to 2026-10-08T12:00:00.000Z --min-occurrences 3 '<抖音视频链接>'
```

更改筛选条件后重新统计本地记录：`npm run numbers:reprocess -- --from 2026-10-08T00:00:00.000Z --min-occurrences 3`。

`--until-end` 最多滚动 300 次；网页明确返回无更多评论、连续 6 次重试没有新增评论或达到上限时停止。默认只统计顶层评论；`--replies N` 额外展开前 N 个回复组并纳入统计，目前不会遍历每组的全部回复。若页面停滞，诊断截图写入 `.phase1/stalled-page.png`。

命令行结果保存在仓库中被忽略的 `.phase1/` 目录；也可用 `--output-dir 路径` 改为其他目录：

- `number-stats.txt`：摘要和达到所选最小次数的号码，便于直接查看。
- `number-stats.csv`：达到所选最小次数的号码及其出现次数。
- `number-stats.json`：完整统计表和采集状态。
- `matched-comments.json`：仅保留时间范围内命中号码的评论正文、发布时间及号码，用于核查误判；不含登录凭证。
- `captured-comments.json`：本次读取的全部评论正文和发布时间，便于调整筛选规则后运行 `npm run numbers:reprocess`，无须重新访问网页；仅保存在本机被忽略的目录。
- `last-report.json`：浏览器加载批次、已读数量、停止原因等。

## 统计口径

- 号码是 **000–999 的原始三位字符串**。`012`、`111`、`121` 都有效；`123` 与 `321` 分开统计，不自动按组选合并。
- 一条评论里的 `681 683` 提取两个号码；`123 456 123` 中的 `123` 只计 1 次。同一个号码在不同评论中出现，则每条评论各计 1 次。
- 按评论 ID 去重；没有有效三位数的评论直接从匹配结果中排除。
- 时间范围按评论发布时间筛选，起止边界均包含；缺少发布时间的评论在设置时间范围时无法判断，旧数据若全部缺少时间会提示重新采集。
- 不提取四位及以上数字、网址中的数字，以及明显是金额、期号、倍数等用途的数字，例如 `100元`、`123期`、`200倍`。
- 表格按出现次数降序、同次数按号码升序排列，TXT/CSV 只导出达到最小次数的号码。页面报告的总评论数只是参考；统计只基于本次实际读取到的评论，不能从部分数据推断全站频次。

纯文本规则无法完全判断发言意图。例如“我没看到有人提 346”也会计入 `346`；请用 `matched-comments.json` 核查边界案例，后续可继续细化规则。
